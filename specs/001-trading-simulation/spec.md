# Feature Specification: Turn-Based Trading Simulation Game

**Feature Branch**: `001-trading-simulation`  
**Created**: 2026-01-08  
**Status**: Draft  
**Input**: KOSPI Top 100 종목 데이터를 활용한 턴제 기반 트레이딩 시뮬레이션 게임. 사용자의 보유 자산 상태에 따라 동적으로 변하는 인터페이스가 핵심.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Daily Stock Selection and Analysis (Priority: P1)

사용자가 게임에 접속하면 현재 턴(거래일)에서 거래 가능한 종목 리스트를 확인하고, 각 종목의 상세 차트와 볼린저 밴드 점수를 분석하여 매매 결정을 내린다.

**Why this priority**: 게임의 핵심 루프를 구성하는 가장 기본적인 기능. 이것 없이는 시뮬레이션 자체가 불가능하다.

**Independent Test**: 사용자가 게임에 접속하여 추천 종목 리스트를 보고, 종목을 클릭하여 차트와 점수를 확인할 수 있으면 이 스토리는 완료된 것으로 간주.

**Acceptance Scenarios**:

1. **Given** 사용자가 시뮬레이션 게임 화면에 진입했을 때, **When** 현재 턴이 시작되면, **Then** 볼린저 밴드 점수 50점 이상인 KOSPI 100 종목 리스트가 화면에 표시된다.
2. **Given** 추천 종목 리스트가 표시된 상태에서, **When** 사용자가 특정 종목을 클릭하면, **Then** 해당 종목의 가격 차트와 상세 점수(볼린저 밴드, RSI, MACD, 거래량 비율)가 표시된다.
3. **Given** 리스트에 추천 종목이 없을 때, **When** 현재 턴이 시작되면, **Then** "오늘은 추천 종목이 없습니다" 메시지와 함께 빈 리스트가 표시된다.

---

### User Story 2 - Conditional Trading Execution (Priority: P1)

사용자가 종목의 보유 여부에 따라 다른 거래 옵션(매수/관망 또는 매도/홀딩)을 제공받고, 선택한 액션을 실행한다.

**Why this priority**: 턴제 게임의 핵심 의사결정 메커니즘. 동적 UI는 사용자 경험의 핵심 차별점이다.

**Independent Test**: 보유하지 않은 종목에는 Buy/Skip 버튼이, 보유 중인 종목에는 Sell/Hold 버튼이 표시되고, 각 버튼을 눌러 액션이 기록되면 완료.

**Acceptance Scenarios**:

1. **Given** 사용자가 보유하지 않은 종목의 상세 화면을 볼 때, **When** 화면이 렌더링되면, **Then** "매수(Buy)" 버튼과 "관망(Skip)" 버튼이 표시된다.
2. **Given** 사용자가 이미 보유 중인 종목의 상세 화면을 볼 때, **When** 화면이 렌더링되면, **Then** "매도(Sell)" 버튼과 "홀딩(Hold)" 버튼이 표시된다.
3. **Given** 사용자가 Buy 버튼을 클릭했을 때, **When** 매수 입력 UI가 표시되면, **Then** 사용자는 매수 금액 또는 수량을 직접 입력할 수 있다.
4. **Given** 사용자가 매수 금액/수량을 입력하고 확인했을 때, **When** 충분한 현금이 있으면, **Then** 해당 종목이 현재가로 매수되고 포트폴리오에 추가된다.
5. **Given** 사용자가 매수 금액/수량을 입력하고 확인했을 때, **When** 현금이 부족하면, **Then** "현금이 부족합니다" 메시지가 표시되고 매수가 실행되지 않는다.
6. **Given** 사용자가 Sell 버튼을 클릭했을 때, **When** 해당 종목을 보유 중이면, **Then** 전량 매도가 실행되고 현금이 증가한다.

### User Story 3 - Turn Progression and Portfolio Update (Priority: P1)

사용자가 모든 결정을 마친 후 "다음 날(Next Day)"을 눌러 턴을 진행하고, 전일 종가 대비 당일 종가 수익률이 포트폴리오에 반영된다.

**Why this priority**: 턴 진행 없이는 게임이 진행되지 않으며, 수익률 반영이 게임의 목표 달성 여부를 결정한다.

**Independent Test**: Next Day 버튼을 눌러 턴이 진행되고, 보유 종목의 평가 금액이 새로운 종가로 업데이트되면 완료.

**Acceptance Scenarios**:

1. **Given** 사용자가 현재 턴의 모든 결정을 완료한 상태에서, **When** "Next Day" 버튼을 클릭하면, **Then** 다음 거래일로 턴이 진행된다.
2. **Given** 턴이 진행될 때, **When** 보유 종목이 있으면, **Then** 각 종목의 평가 금액이 새로운 종가 기준으로 업데이트된다.
3. **Given** 턴이 진행될 때, **When** 모든 계산이 완료되면, **Then** 포트폴리오 요약(총 자산, 평가 손익, 수익률)이 화면에 표시된다.

---

### User Story 4 - Portfolio State Display (Priority: P2)

사용자가 현재 포트폴리오 상태(현금, 보유 종목, 평균 매수가, 평가 손익)를 실시간으로 확인한다.

**Why this priority**: 의사결정에 필요한 정보지만, 핵심 게임플레이 없이 단독으로는 가치가 없다.

**Independent Test**: 포트폴리오 패널에서 현금, 보유 종목 리스트, 각 종목의 평균 매수가와 평가 손익이 표시되면 완료.

**Acceptance Scenarios**:

1. **Given** 게임 화면이 로드된 상태에서, **When** 포트폴리오 패널을 확인하면, **Then** 현재 보유 현금이 표시된다.
2. **Given** 보유 종목이 있을 때, **When** 포트폴리오 패널을 확인하면, **Then** 각 종목의 종목명, 보유 수량, 평균 매수가, 현재가, 평가 손익(금액 및 %)이 표시된다.
3. **Given** 매수 또는 매도가 실행된 후, **When** 화면이 갱신되면, **Then** 포트폴리오 상태가 즉시 반영된다.

---

### User Story 5 - Real-time Backtest Report (Priority: P2)

사용자가 게임 중 언제든지 현재까지의 누적 거래 기록을 기반으로 백테스트 보고서를 열람하여 자신의 전략 성과를 점검한다.

**Why this priority**: 학습 및 전략 개선을 위한 피드백 루프 제공. 핵심 게임플레이 완성 후 추가되어도 무방.

**Independent Test**: "현재 리포트 보기" 버튼을 눌러 모달에서 누적 수익률 그래프, MDD, 승률 등이 표시되면 완료.

**Acceptance Scenarios**:

1. **Given** 최소 1턴 이상 진행된 상태에서, **When** "현재 리포트 보기" 버튼을 클릭하면, **Then** 백테스트 보고서가 모달 또는 슬라이드 오버 형태로 표시된다.
2. **Given** 보고서 모달이 열린 상태에서, **When** 내용을 확인하면, **Then** 누적 수익률 그래프(Equity Curve), MDD, 승률, 손익비, 종목별 기여도가 표시된다.
3. **Given** 보고서 모달이 열린 상태에서, **When** 닫기 버튼을 클릭하면, **Then** 모달이 닫히고 게임 화면으로 복귀한다.

---

### User Story 6 - Trade History JSON Export (Priority: P3)

모든 매매 이력이 기존 시스템과 호환되는 JSON 형식으로 실시간 누적 기록되어, 외부 분석이나 시스템 연동에 사용될 수 있다.

**Why this priority**: 시스템 통합 기능으로, 핵심 게임플레이와 독립적. 나중에 추가해도 사용자 경험에 큰 영향 없음.

**Independent Test**: 게임 중 매매 발생 시마다 JSON 형식의 거래 기록이 생성되고, 이를 다운로드하거나 조회할 수 있으면 완료.

**Acceptance Scenarios**:

1. **Given** 매수 또는 매도가 실행될 때마다, **When** 거래가 완료되면, **Then** 해당 거래가 JSON 형식으로 거래 이력에 추가된다.
2. **Given** 거래 이력이 누적된 상태에서, **When** 사용자가 "거래 내역 내보내기" 기능을 사용하면, **Then** 기존 백테스트 시스템과 호환되는 JSON 파일이 다운로드된다.

---

### Edge Cases

- **추천 종목 0개**: 볼린저 밴드 점수 50점 이상인 종목이 없을 경우, 빈 리스트와 안내 메시지 표시
- **현금 부족 매수 시도**: 매수 금액이 보유 현금을 초과할 경우, 에러 메시지와 함께 거래 거부
- **마지막 거래일 도달**: 시뮬레이션 기간의 마지막 날에 도달하면 게임 종료 화면 및 최종 성과 요약 표시
- **동일 종목 중복 매수**: 이미 보유 중인 종목을 다시 추천받은 경우, 매수가 아닌 홀딩/매도 옵션만 제공
- **게임 중 새로고침/이탈**: 진행 상태가 자동 저장되어 복귀 시 마지막 상태에서 재개
- **유효하지 않은 기간 선택**: 데이터가 없는 기간이나 미래 날짜 선택 시 에러 메시지 표시 및 재선택 요청

## Requirements *(mandatory)*

### Functional Requirements

**인증**
- **FR-000**: 시스템 MUST 기존 PEM 파일 기반 인증 시스템을 통해 로그인된 사용자만 게임에 접근할 수 있게 해야 한다

**게임 초기화 및 설정**
- **FR-001**: 시스템 MUST 게임 시작 시 초기 자본금(기본값: 1억원)과 시뮬레이션 기간(시작일/종료일)을 설정할 수 있어야 한다
- **FR-001a**: 시스템 MUST 사용자가 yfinance 데이터가 존재하는 범위 내에서 임의의 과거 기간을 자유롭게 선택할 수 있게 해야 한다
- **FR-002**: 시스템 MUST KOSPI Top 100 종목 데이터를 기반으로 시뮬레이션을 제공해야 한다

**턴 기반 게임플레이**
- **FR-003**: 시스템 MUST 매 턴 시작 시 볼린저 밴드 점수 50점 이상인 종목을 필터링하여 추천 리스트로 제공해야 한다
- **FR-004**: 시스템 MUST 추천 종목 클릭 시 해당 종목의 가격 차트와 상세 지표(볼린저 밴드, RSI, MACD, Volume Ratio)를 표시해야 한다
- **FR-005**: 시스템 MUST 사용자의 종목 보유 여부에 따라 다른 액션 버튼을 동적으로 표시해야 한다
- **FR-006**: 시스템 MUST "Next Day" 버튼 클릭 시 다음 거래일로 턴을 진행하고 수익률을 반영해야 한다

**거래 실행**
- **FR-007**: 사용자 MUST 추천 종목에 대해 매수(Buy) 또는 관망(Skip)을 선택할 수 있어야 한다
- **FR-007a**: 시스템 MUST 매수 시 사용자가 매수 금액 또는 수량을 직접 입력할 수 있는 UI를 제공해야 한다
- **FR-008**: 사용자 MUST 보유 종목에 대해 매도(Sell) 또는 홀딩(Hold)을 선택할 수 있어야 한다
- **FR-009**: 시스템 MUST 매수 시 현금 잔액을 확인하고, 부족할 경우 거래를 거부해야 한다
- **FR-010**: 시스템 MUST 매도 시 전량 매도를 실행하고 현금을 업데이트해야 한다

**포트폴리오 관리**
- **FR-011**: 시스템 MUST 현재 보유 현금, 종목별 보유 수량, 평균 매수가, 실시간 평가 손익을 관리해야 한다
- **FR-011a**: 시스템 MUST 동시 보유 종목 수에 제한을 두지 않아야 한다 (현금이 허용하는 한 무제한)
- **FR-012**: 시스템 MUST 거래 발생 시 포트폴리오 상태를 즉시 갱신해야 한다

**백테스트 리포트**
- **FR-013**: 시스템 MUST 매 턴 종료 시 누적 거래 기록을 기반으로 실시간 백테스트 보고서 데이터를 생성해야 한다
- **FR-014**: 시스템 MUST 사용자가 게임 중 언제든지 백테스트 보고서를 모달 형태로 열람할 수 있게 해야 한다
- **FR-015**: 시스템 MUST 보고서에 누적 수익률 그래프, MDD, 승률, 손익비, 종목별 기여도를 포함해야 한다

**데이터 통합**
- **FR-016**: 시스템 MUST 모든 매매 이력을 기존 백테스트 시스템과 호환되는 JSON 형식으로 기록해야 한다
- **FR-017**: 시스템 MUST 게임 진행 상태를 사용자 계정에 자동 저장하여 중단 후 재개가 가능해야 한다

### Key Entities

- **GameSession**: 시뮬레이션 게임 세션. 시작일, 종료일, 초기 자본금, 현재 턴(거래일), 게임 상태(진행중/완료), 현금 잔액을 포함 (포트폴리오 정보 내장)
- **SimulatedPosition**: 게임 내 가상 포지션. 종목 코드, 보유 수량, 평균 매수가, 현재 평가 금액, 미실현 손익. GameSession에 종속
- **SimulatedTrade**: 게임 내 가상 거래 기록. 거래 유형(BUY/SELL), 종목 코드, 수량, 가격, 거래일, 수익률
- **DailyRecommendation**: 일별 추천 종목 리스트. 매 턴마다 실시간 계산됨 (별도 저장 없음 - computed entity)

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 사용자가 게임 시작부터 첫 거래 완료까지 3분 이내에 수행할 수 있다
- **SC-002**: 추천 종목 리스트 로딩이 2초 이내에 완료된다
- **SC-003**: 종목 상세 차트 및 지표 표시가 1초 이내에 완료된다
- **SC-004**: 턴 진행(Next Day) 클릭 후 결과 반영이 3초 이내에 완료된다
- **SC-005**: 백테스트 보고서 모달 로딩이 2초 이내에 완료된다
- **SC-006**: 사용자가 보유 여부에 따른 올바른 버튼(Buy/Skip 또는 Sell/Hold)을 100% 정확하게 제공받는다
- **SC-007**: 게임 중단 후 재접속 시 마지막 상태에서 100% 복구된다
- **SC-008**: 내보낸 JSON 거래 기록이 기존 백테스트 시스템에서 100% 호환되어 분석 가능하다

## Clarifications

### Session 2026-01-08

- Q: 매수 버튼 클릭 시 얼마나 매수하는가? → A: 사용자가 매수 금액/수량 직접 입력
- Q: 시뮬레이션 기간의 기본값과 설정 방식은? → A: 사용자가 임의의 과거 기간 자유 선택 (제한 없음)
- Q: 시뮬레이션 게임은 로그인이 필요한가? → A: 로그인 필수 - 기존 PEM 파일 기반 인증 시스템 사용

## Assumptions

- 시뮬레이션 기간은 2020년부터 현재까지의 KOSPI 데이터를 기반으로 설정된다 (yfinance 데이터 기준, 2020년 이전 데이터도 축적 예정)
- 초기 자본금 기본값은 1억원(KRW 100,000,000)이며, 사용자가 게임 시작 전 변경 가능하다
- 매매는 해당 거래일의 종가 기준으로 체결된다
- 슬리피지, 거래 수수료, 세금은 시뮬레이션에서 고려하지 않는다 (순수 전략 테스트 목적)
- 매수 시 사용자가 금액/수량을 직접 입력하며, 매도 시에는 전량 매도만 가능하다
- 기존 백테스트 시스템의 JSON 형식은 현재 `/api/backtest` 응답 형식과 동일하다
